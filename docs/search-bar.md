# 공통 검색창

Issue #27 · Figma input_search `3081:10672` · 최신 기능명세 SCR-01-02 / SCR-02 검색창 기준입니다.

## 사용

```tsx
<SearchBar
  value={keyword}
  onValueChange={setKeyword}
  hasSelectedFilters={hasSelectedFilters}
  onSearch={handleSearch}
/>
```

- `value`: 입력 중인 원문. 부모가 제어합니다.
- `onValueChange`: 입력 변경만 알립니다. 입력할 때마다 API를 호출하지 않습니다.
- `onSearch`: 버튼 또는 Enter 제출 시 앞뒤 공백을 제거한 검색어를 한 번 전달합니다.
- `hasSelectedFilters`: 유효한 선택 필터가 있으면 빈 검색어도 제출할 수 있습니다. 유효 필터 판정은 부모가 합니다.
- `disabled`: 입력·제출을 함께 막습니다.
- `ariaLabel`: 메인·검색 결과 등 여러 검색 영역을 구별합니다.

입력 최대 길이는 30자입니다. 한글 조합 중 Enter는 제출을 막습니다. 검색어·필터 모두 없거나 공백만 있으면 제출을 막고 추가 안내 문구는 표시하지 않습니다. 특수문자를 매칭에서 무시하는 규칙은 서버/조회 계층의 책임으로 남깁니다.

## 디자인·검수 범위

- 기본·포커스·입력·입력 후 상태: 일반 테두리 gray-300, 포커스 gray-500, 빈 상태 버튼 gray-200, 검색 가능 버튼 yellow-400.
- 원본 높이 58px, 검색 아이콘 24×24px, 버튼 112×40px, 부모가 너비를 정합니다. 853px·898px·640px에서 확인합니다.
- 로컬/Preview의 `/setup/search-bar`에서 상태와 콜백을 확인합니다. 운영 빌드에는 확인용 라우트를 포함하지 않습니다.
- 검색 버튼의 Figma 글꼴은 HGSoftGGothicssi 80g이나 현재 develop에는 해당 웹폰트가 없습니다. 기존 Pretendard 700으로 표시하는 차이가 남아 있습니다. 임의의 폰트 파일을 추가하지 않습니다.
- 손승현의 기본 Input·Button은 작업 시점 develop에 없어서 검색창 안에 네이티브 입력·버튼을 사용합니다. 원본 검색창의 형태·크기·이벤트를 보존할 수 있는 공통 UI가 준비되면 조합합니다. 별도 범용 Input·Button을 중복 생성하지 않습니다.

## 후속 연결

검색창 컴포넌트는 필터·인기 검색어 전체 카드를 구현하지 않습니다. 부모 화면이 URL 갱신·페이지 이동·최근 검색 저장·공고 목록 재조회를 연결하고, 입력 중인 값과 검색 실행한 값을 구분합니다. 이번 작업에 API와 페이지 조립 완료를 포함하지 않습니다.

## 이번 작업에서 확인한 결과

- `pnpm check` 통과: lint·typecheck·기존 날짜 테스트 30개·build·format:check. 새 검색창 전용 자동 테스트를 추가한 결과는 아닙니다.
- Chrome에서 빈 입력·공백·전체 비활성의 제출 차단, 버튼·Enter 각각 1회 콜백, 앞뒤 공백 제거, 필터만 검색, 30자 초과 입력 방지를 확인했습니다.
- 853px·898px·640px에서 높이 58px, 버튼 112×40px, 원본 아이콘 24×24px, 가로 넘침 없음을 측정했습니다.
- 한글 조합 중 Enter 방어 코드는 포함했습니다. 실제 운영체제 한글 IME 조작은 이번 브라우저 검증에서 수행하지 않았으므로 수동 확인이 남아 있습니다.
